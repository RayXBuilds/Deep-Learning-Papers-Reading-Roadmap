## 问题

固定类别的图像分类器通常输出一个预定义标签表。若想用自然语言指定新的类别，训练时如何让视觉表示和文字描述可以直接比较？CLIP 使用图像—文本配对作为监督，训练两个编码器，把输出映射到共同的向量空间；推理时可把候选类别写成文本，再和图像比较。方法依据见原文 §2.3 与 §3.1.2。

这里有三个应分开检查的问题：训练样本中谁和谁配对；编码器如何产生表示；测试时提供了哪些候选文本。后面的手算实验固定第二项，只改变第一、三项，不能据此证明模型已经学会视觉语义。

## 方法与关键推导

### 从配对索引到双向损失

以下是对原文 §2.3、Figure 3 伪代码的维度展开。一个批次有 N 对样本 `(image_i, text_i)`。图像和文本各自经过编码器、线性投影和 L2 归一化，得到 U、V ∈ R^(N×d)，每行长度为 1。令 a = exp(t) = 1/τ > 0，则

```text
S = a U Vᵀ                         # N×N 分数矩阵
p(text_j | image_i) = exp(S_ij) / Σ_k exp(S_ik)
p(image_i | text_j) = exp(S_ij) / Σ_k exp(S_kj)
L = -(1 / 2N) Σ_i [log p(text_i | image_i) + log p(image_i | text_i)]
```

行方向让每张图在批内找配对文字；列方向让每段文字在批内找配对图片。标签是对角线索引，不能把它理解成“所有非对角线在语义上一定不相关”。两份相同内容也可能有不同索引。

我们可以直接推导两个实现检查：同时用同一置换重排图像与文本，只改变编号，损失不变；只打乱文字而保留对角标签，实际改变监督关系。另一个检查是 L(S) = L(Sᵀ)，因为转置交换了两个方向。只计算一个方向时，这一性质一般不成立。

### 温度与候选集合分别改变什么

固定 U、V 时，共同乘正数 a 不改变分数排序，却改变 softmax 的集中程度。原文 §2.5 使用可学习温度，并描述对 logit scale 的上限约束。官方 `forward` 中可核实的是归一化、`exp(logit_scale)` 和矩阵乘法；这不能单独证明完整训练过程实现了论文描述的所有约束。

自己的手算例子：归一化向量 `[1,0]` 与候选 `[1,0]`、`[0,1]` 的分数在 a=2 时为 `[2,0]`，首项概率约 0.881。再加一个同分数候选得到 `[2,0,2]`，首项概率降到约 0.468，图像与原候选的相似度完全没变。因此候选集合内的 softmax 值不是脱离候选集的通用置信度；添加重复类别也会分走概率。

### 从编码器到零样本分类

原文 §2.4 使用修改的 ResNet 或 ViT 作为视觉编码器，文本侧是带因果掩码的 Transformer，取结束标记处的表示。它没有在这一步用 BERT 的 MLM 损失，也不是图文 token 的交叉注意力融合。

§3.1.2 将类别描述编码为文本向量，以图文相似度分类；§3.1.4 的提示模板和提示集成说明，类名怎样写进句子也是评价配置。读实验时要固定类别表、模板和模型版本。不要把换了候选文本后的结果当作纯粹的视觉编码器改进。

## 与其他论文的关系

- [ViT](vit.md) → CLIP：**组件联系**。块序列编码器可提供图像表示；CLIP 的配对目标不是 ViT 的块投影定义。CLIP 也有 ResNet 视觉分支，不能把两者视为同义词。
- [Transformer](transformer.md) → CLIP：**组件联系**。文本编码器使用序列注意力，图文匹配发生在两个编码器的输出向量之间。自注意力与图文配对分数是不同计算。
- [BERT](bert.md) ↔ CLIP：**目标对照**。MLM 对选中 token 预测原词，CLIP 对批内配对索引作分类；即使共享 Transformer 组件，标签单位、可见性与损失位置也不同。
- [AdamW](adamw.md) → CLIP：**训练组件联系**。原文 §2.5 的优化设置可结合解耦衰减阅读；当前实验固定向量，没有验证优化器、收敛或泛化。

这些是教学关联，不表示 CLIP 是从 BERT 连续替代而来的单一路线。

## 可验证实验

[脚本](../experiments/clip_objective.py) · [协议与实测](../experiments/results/clip-objective.md) · [原始 JSON](../experiments/results/clip-objective.json)

```bash
python3 experiments/clip_objective.py --output /tmp/clip-objective.json
python3 -m unittest discover -s experiments -p 'test_clip_objective.py' -v
```

输入是两对二维正交单位向量，a=2，CPU 标准库，无随机数（seed=null）、编码器或训练。正配对损失为 0.126928；只交换文字后为 2.126928；同时交换两侧恢复原值。两对表示全部相同的负对照得到 log(2)≈0.693147：对角标签仍要求区分索引，但当前向量没有可区分信息。

7 项机制检查通过，6 项语义测试通过，包括独立非对称矩阵的双向手算。等式容差 1e-12；配错标签的损失增量要求 >1；概率变化只检查本例方向。具体输入、比较值与边界见报告。

## 局限与思考

固定二维向量只能检查目标语义，不能证明真实图文编码器可学到有用表示。重复向量的结果也不能估计现实数据里“假负例”的频率；更不能推导 CLIP 必然坍缩。训练、数据分布与表示可分性需要另外实验。

下一步可操作的问题：使用官方固定权重和独立的小型图像集，在保持类别、划分、模型和图像预处理不变时，仅比较裸类名与固定模板。需同时报告 top-1、逐类差异及候选列表，不能用测试标签挑出最佳提示后仍称其为未经选择的零样本结果。该实验尚未实现。
