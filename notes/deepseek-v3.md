# DeepSeek-V3：路由器怎样兼顾专家分工和设备负载？

DeepSeek-AI（Aixin Liu 等），《DeepSeek-V3 Technical Report》。2024-12-27 首稿，2025-02-18 修订，arXiv 技术报告。[版本原文](https://arxiv.org/abs/2412.19437v2) · [作者实现或发布入口](https://github.com/deepseek-ai/DeepSeek-V3)

## 问题

稀疏 MoE 只为每个 token 激活一部分专家。若多数 token 都选同一专家，其设备会拖慢整批。若强制每段文字平均使用专家，领域词又可能被分给不合适的专家。报告将“被选中”和“贡献多少”拆成两个量。

## 方法与关键推导

对 token $t$，路由器算出 sigmoid 亲和度 $s_{it}$。先按 $s_{it}+b_i$ 选 top-K，再在选中集合 $S_t$ 中按原始分数设置 $g_{it}=s_{it}/\sum_{j\in S_t}s_{jt}$。共享专家另走常开路径。批内过载的路由专家下调偏置，欠载的上调；当集合没有变化，偏置也不会改变输出混合权重。报告还保留很小的序列级辅助损失，以限制极端不平衡。

另一个干预是多 token 预测（MTP）。第一个附加层把当前位置表示与下一个已知 token 的嵌入合并，经因果模块预测再下一项。训练时这个目标多给主干一条梯度路径；常规推理可移除预测模块，表 4 就按此口径比较。

## 原论文证据

第 4.5.2–4.5.3 节表 5 及批级辅助损失对照显示，放宽到批内平衡也能取得相近效果，单凭总分无法把收益全归于偏置更新。表 4 固定两档模型各自的训练 token 数，较大档加 MTP 后 HumanEval pass@1 从 44.5 到 53.7，而 MMLU 从 67.5 到 66.6。任务间的差异是解读该消融的重要部分。

## 与其他论文的关系

[DeepSeek-R1](deepseek-r1.md) 使用 V3-Base 作为后训练起点。MoE 改变每个 token 的前馈计算，R1 的组内奖励改变采样回答的更新方向，两项干预发生在不同层次。

## 可验证实验

本批未运行路由、MTP 或 V3 训练。可冻结三个专家输出与亲和度，逐步增大一个未入选专家的偏置；越过 top-K 边界前要求混合输出完全相同，越界后检查权重仍由原亲和度归一化。

## 局限与思考

负载统计依赖批的组成。若训练时混合多个领域，部署时却连续收到同一领域请求，平均负载会掩盖短时排队。需要分开记录每批最忙专家的 token 数和等待时间。
